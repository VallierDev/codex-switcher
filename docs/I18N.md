# Internationalization

## 中文

### 工作方式

- 简体中文是源码语言，也是无法识别系统语言或没有对应翻译时的默认语言。
- 应用启动时优先读取系统语言；Linux 上如果进程只有 `C/POSIX` 通用语言，则回退到 `/etc/default/locale`，然后在 `src/i18n/index.ts` 的 `appLocales` 中匹配语言前缀。
- 如果用户没有手动选择语言，应用会根据系统语言自动选择已提供的翻译；未识别或未提供翻译时使用简体中文。顶栏菜单只显示可用语言，用户手动选择的语言保存在本机 `localStorage` 中，并覆盖后续自动检测。
- `src/i18n/runtime.ts` 负责翻译 React 渲染出的文本、常用可访问性属性、浏览器对话框和通知。
- Tauri 后端通过 `set_app_locale` 与前端使用相同语言；OAuth 页面、托盘菜单和系统通知放在 `src-tauri/src/i18n/` 中。

### 添加新语言

1. 复制 `src/i18n/ru.ts` 为新的语言文件，实现并导出一个 `UiLocale`。
2. 在 `src/i18n/index.ts` 导入该文件，并向 `appLocales` 添加语言代码、系统语言前缀、本地语言名称、旗帜、翻译对象和 `contributors` 中的翻译贡献者。可以为每位贡献者添加可选的个人主页 URL。
3. 如果该语言需要翻译后端可见文本，复制 `src-tauri/src/i18n/ru.rs`，实现 `BackendLocale`，然后在 `src-tauri/src/i18n/mod.rs` 的 `BACKEND_LOCALES` 中注册。
4. 优先翻译完整句子。动态消息中的 `{}`、`{name}` 等占位符数量必须与中文源文本一致。
5. 运行 `npm run check:i18n`、`npm run build` 和 `cargo check --manifest-path src-tauri/Cargo.toml`。

`contributors` 会在“关于”中自动生成翻译贡献者列表。该列表仅在当前语言不是源语言时显示。每个新的语言文件还必须翻译列表标题 `翻译` 和说明 `感谢帮助应用支持更多语言的贡献者`。语言的本地名称和贡献者姓名不会再次翻译。

不要直接把组件中的中文替换为另一种语言。中文必须继续作为可维护的源码和回退语言。

## English

### How it works

- Simplified Chinese is the source language and the fallback when the system locale is unknown or no translation is available.
- At startup, the app reads the system locale and matches its prefix against `appLocales` in `src/i18n/index.ts`. On Linux, a generic `C/POSIX` process locale falls back to `/etc/default/locale`.
- When the user has not chosen a language manually, the app detects the system locale and selects an available translation; unknown or unavailable locales fall back to Simplified Chinese. The header menu lists only available languages. A manual choice is stored in `localStorage` and disables later automatic switching.
- `src/i18n/runtime.ts` translates React-rendered text, common accessibility attributes, browser dialogs, and notifications.
- The frontend synchronizes the selected locale with Tauri through `set_app_locale`. OAuth pages, native tray items, and system notifications live in `src-tauri/src/i18n/`.

### Adding a language

1. Copy `src/i18n/ru.ts` to a new locale file and export a `UiLocale` implementation.
2. Import it in `src/i18n/index.ts`, then add its locale code, system-language prefixes, native name, flag, translation object, and translation contributors in `contributors` to `appLocales`. Each contributor may have an optional profile URL.
3. If native backend text must be translated, copy `src-tauri/src/i18n/ru.rs`, implement `BackendLocale`, and register it in `BACKEND_LOCALES` in `src-tauri/src/i18n/mod.rs`.
4. Prefer complete messages over fragments. Preserve the number of `{}` and named placeholders from the Chinese source text.
5. Run `npm run check:i18n`, `npm run build`, and `cargo check --manifest-path src-tauri/Cargo.toml`.

The `contributors` entries automatically populate the translation credits in About. The credits are shown only when the active language differs from the source language. Every new locale file must also translate the credits heading `翻译` and description `感谢帮助应用支持更多语言的贡献者`. Native language names and contributor names are displayed as registered and are not translated again.

Do not replace Chinese strings directly in components. Chinese must remain the maintainable source and fallback language.

## Русский

### Как это работает

- Упрощённый китайский остаётся исходным языком и включается, если системная локаль не определена или для неё нет перевода.
- При запуске приложение читает системную локаль и сопоставляет её префикс с реестром `appLocales` в `src/i18n/index.ts`. В Linux при общей локали процесса `C/POSIX` используется `/etc/default/locale`.
- Если пользователь ещё не выбирал язык вручную, приложение определяет системную локаль и выбирает доступный перевод; при неизвестной локали или отсутствии перевода используется упрощённый китайский. В меню шапки отображаются только доступные языки. Ручной выбор сохраняется в `localStorage` и отключает дальнейшее автоматическое переключение.
- `src/i18n/runtime.ts` переводит текст, созданный React, основные атрибуты доступности, браузерные диалоги и уведомления.
- Frontend передаёт выбранную локаль Tauri-командой `set_app_locale`. OAuth-страницы, нативное tray-меню и системные уведомления находятся в `src-tauri/src/i18n/`.

### Как добавить язык

1. Скопируйте `src/i18n/ru.ts` в файл новой локали и экспортируйте реализацию `UiLocale`.
2. Импортируйте её в `src/i18n/index.ts`, затем добавьте в `appLocales` код локали, префиксы системного языка, самоназвание языка, флаг, объект перевода и авторов перевода в `contributors`. Для каждого автора можно указать необязательную ссылку на профиль.
3. Если нужен перевод видимых строк backend, скопируйте `src-tauri/src/i18n/ru.rs`, реализуйте `BackendLocale` и зарегистрируйте локаль в `BACKEND_LOCALES` из `src-tauri/src/i18n/mod.rs`.
4. Предпочитайте переводы целых сообщений фрагментам. Сохраняйте число `{}` и именованных подстановок из исходной китайской строки.
5. Выполните `npm run check:i18n`, `npm run build` и `cargo check --manifest-path src-tauri/Cargo.toml`.

Записи `contributors` автоматически формируют список авторов переводов в разделе «О программе». Список показывается, только когда активный язык отличается от исходного. В файле каждой новой локали также нужно перевести заголовок `翻译` и описание `感谢帮助应用支持更多语言的贡献者`. Самоназвания языков и имена участников выводятся как зарегистрированы и повторно не переводятся.

Не заменяйте китайские строки непосредственно в компонентах. Китайский должен оставаться поддерживаемым исходным и резервным языком.
